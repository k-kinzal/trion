# Names and target constraints

A package begins with `package NAME`. The same syntax and reading rules apply throughout the package and its dependencies. [Grammar](../grammar.trion) · [Pattern ledger](../patterns/ledger.toml)

## Names and scopes

Each namespace owns a table of canonical names. An explicit local declaration wins over a name brought into scope by an import. Otherwise exactly one importing namespace may supply an unqualified name. A qualified name must identify a namespace and an exported name in it. An ordinary descriptive occurrence in inferred mode may introduce a local name when its namespace has no supplier. Mutually importing namespaces need an explicit owner when both could introduce the same name. Resolution considers the whole package, so declarations and abbreviations may be forward referenced. Inflection uses fixed language rules and is independent of the declaration of an unrelated name.

`term NAME: KIND`, `primitive NAME`, `predicate NAME(TYPES)`, and `alias NAME = TARGET` supply vocabulary. `entity` and `object` are compatible argument positions. `class` identifies a unary nominal classification, and `relation` identifies a nominal relationship with an owner. An attribute, a value and an action have different uses. A `predicate` signature checks the actor, direct object, nominal roles in written order, and any content proposition. Active clauses and passives with a written agent use the same argument order. Checks cover responses, conditions and verbal relative clauses. A named argument type resolves in the signature's own scope. A declaration of individuals supplies the type of its variables. A classification stated in a contract leaves the signature unchanged. An intentionally uninterpreted `primitive` introduces a name. In declared mode, the declaration requirement still applies to nouns and values.

`individuals` selects the bounded reading over explicit carriers. `system` and `environment` assign responsibility. Existence and closed value domains are stated separately. A description can both introduce a name and constrain it. Only the associated formula constrains it.

## Target constraints

`The codec is a specification language` asserts the unary classification of the representative named `codec`. A second classification may hold at the same time. `The codec is a member of the network` asserts the binary relationship with arguments `codec` and `network`. The relationship belongs to the first argument for A/G classification. Pure identity uses an alias. A bare definite complement with distinct names is outside the representative fragment.

The nominal complement and its relative clause are parsed by the same noun-phrase parser as the right side of `means`. `The codec is a specification language that is also a controlled language` asserts both classifications of `codec`. Positive conjunction here has the same meaning as the two corresponding descriptions of that representative. Negating the compound denies their conjunction. A relative clause that needs quantification, action timing or content semantics requires a separate supported form. Representative classification and this nominal relationship are static. Attribute value and action timings retain their existing readings.

A generic representative description about a class is conditional on the existence of its representative. To distinguish members of a class, declare `individuals`. For example, with `individuals guest, user`, `Each guest is a user` is a one-way inclusion over a shared bounded carrier. It permits an empty guest class. `There is a guest` adds existence. An unconditional compound classification such as `Each guest is a user that is a subscriber` checks both classes at the same slot of that carrier. `Some guest is a user that is a subscriber` requires a slot satisfying all three classes. The same rule handles Boolean class expressions and their negation. Enumeration of the values of one attribute uses `is one of …` and the existing enumeration rules.

The subject of a structured description determines responsibility. The existing A/G rules distribute environment assumptions and place conditions about the system within its guarantee. Using a name in a condition adds neither an assertion nor an existence claim.

A `system` declaration on an individual type assigns its membership facts to the system. Explicit individual types that share a carrier also share one responsibility for the actions of its slots. Conflicting system and environment declarations for the same carrier are diagnosed at the declarations.

In a representative condition, `a command exists` tests the same fact that `There is a command` asserts. The condition leaves that fact free. An ordinary verbal relation retains its arguments and manner. For example, `While an editor exists, the editor shows a text to the person` requires the action with its recipient when the editor exists.

With declared individuals, a static compound membership may occur in a condition or in the description of an already bound individual. `While a codec is a format that is a dialect, the codec shall start` tests both classes of the very same codec. The classification supplies a domain guard. An event or a changing state in another clause of the statement supplies its own timing.

## Aliases and abbreviations

`alias serializer = codec` gives an existing symbol an extra spelling. The new spelling resolves to the same target before formulas are constructed. The match covers the full name. An alias for `buffer` leaves `buffer status` independent. A local declaration of `codec` takes precedence over an imported alias with that spelling. Alias targets and words in a definition must resolve to one owning namespace.

`A monitored service means a telemetry service that is a monitoring service` introduces a fresh unary abbreviation with one argument, the subject of the membership predicate. Its body is a Boolean nominal formula over resolved classes. Each use substitutes the body with that subject. For every representative the abbreviation holds exactly when the body holds. Expansion preserves the arguments and the static interpretation of the classes. Cycles, independent explicit declarations of the same name and unsupported bodies are errors. Uses of a defined class as a representative or as an action are type errors. Abbreviations can be adjacent and can be unused.

This is a conservative extension for a fresh name. Removing the spelling or expanding it leaves identical formulas over the old symbols. The guarantee applies to fresh abbreviations. Introducing an abbreviation with the spelling of a previously inferred class in an existing document changes the reading of its uses and requires migration review.

## Specification reference and application

`refer DEPENDENCY` resolves a manifest dependency key to its package. The key serves as the local name of the reference. The conversion report and MMT form record the resolved package and namespaces separately from applications. Public names are visible in the namespace that writes the reference. The dependency's ordinary statements supply name origins but no target contracts. `use` imports the dependency's contracts and form-role activations.

A form role from a reference can be applied using `bind TARGET as DEPENDENCY.ROLE`. The role's format and required forms are checked for the bound target. Its automatic activation patterns are used when a package is taken with `use`. The binding and any violated format are recorded as `form` in the conversion report and MMT. With `refer wire` pointing to the gRPC package, `bind API as wire.service` checks the method names of `API` under the selected gRPC role.

The same binding can select a sentence classification backed by an explicit unconditional enumeration. With `refer patterns` pointing to EARS, `bind API as patterns.syntax.` checks the EARS forms of sentences whose subject resolves to `API`. The enumeration is read as a format interface, and a violation names the sentence, binding and source enumeration. Other targets in the namespace may use other forms. A namespace can select EARS for all its sentences with `use`.

`apply DEPENDENCY as INSTANCE with SOURCE = TARGET, …` instantiates contracts from a reference in the same namespace. Each substituted source symbol needs a target with a compatible use, and each source actor needs a target with matching declared responsibility. Mapping a source actor can use a target introduced by a responsibility declaration. If the source asserts the actor's existence, that contract applies to the target. An ambiguous target requires a qualified name. The instance identifier is unique in the applying package. Assumptions authored in the referenced specification apply to the contracts of that instance. A shared condition block further narrows their scope. Each mapped contract carries its instance identifier, original source text and location. The conversion report and MMT form also carry the package, its `use` dependencies, canonical mapping and source statement identifiers. Source citations retain their evidence role.

The application follows the transitive `use` dependencies, including each package once. Each source type declared by `individuals` maps to a target type also declared by `individuals`. Representatives map to representatives. A declared verbal predicate maps to a declared predicate with the corresponding signature. Verbs with an implicit action frame keep their spelling. A derived class expands in its declaring namespace and its underlying classes take the instance mapping. An explicit source form binding is carried to its mapped subject. A source role activated by a statement about a representative retains its condition and response. Its role applies when the mapped statement is active and its response holds. A literal name in a bound role's pattern must keep its identity under application. Role parameters can stand for mapped names.

If a source package applies a dependency, the enclosing application composes the source-to-interface mapping with its mapping to the final target. The inner assumptions apply within that inner instance and its descendants. An outer document assumption can also reach its nested contracts. A source refinement is checked over the same mapped statements and responsibility boundary. Cycles in the application dependencies are rejected.

The application checks simple existences, static nominal predicates, and obligations with simple verbal or nominal frames, nominal argument roles and supported numeric time roles. Source statements outside this fragment require a supported interface. For a sentence outside the fragment, the application diagnostic identifies its original statement and location. MMT readback preserves the application hierarchy. Proof obligations use the mapped formulas.

## Authoring and inspection

The [telemetry example](../examples/symbols/trion.trion) starts with the target's responsibility and existence, then states its classifications, ownership, quantity and behavior. It applies one specification twice and uses consecutive abbreviations for a repeated classification condition. In the editor, completion and hover use the resolved symbol table. Go to Definition can lead to an introducing description. When imports make a spelling ambiguous, the quick fix offers the available qualified spellings. The generated glossary links symbols to their originating and constraining statements. The JSON report and MMT carry resolved identities, owners, kinds, signatures and source locations. Two spellings of the same symbol share one identity in these outputs.

## Proof subjects

A saved result identifies the package inputs and generated proof obligations by content digests. The package digest covers the source files and dependency manifests. The obligation digest covers the questions and formulas that the prover reads. `use` includes a dependency's contracts. `refer` supplies access to the dependency's names for an explicit application.

A spelling-only alias can be introduced automatically when both spellings already denote the same resolved symbol and the alias creates no collision. Arbitrary `means` clauses, definitions with quantifiers and content, and replacements of a definition with a description require review of the old and new formulas. In particular, converting a two-way definition into a one-way classification changes what a counterexample may assert. [Migration and verification record](../../record/decisions/symbols.md)

The implementation reports claims only at the bounds written in MMT. Expansion readback uses the original requested bounds. The symbol table and source locations are annotations. Proof obligations use the formulas and the stated responsibility and bounds. The English-to-formula convention and the correctness of a responsibility declaration are outside the proof. The independent bounded reader checks unconditional classifications and supported Boolean classifications in conditions and descriptions. It records where it cannot rederive a sentence from its surface or compare a generated contract. Population questions in conditions over individuals and compound predicates with owned or temporal relative clauses need additional bounded rules. When a refinement fails, the proof report distinguishes an excluded environment from a behaviour that the details allow. Where a checked counterexample has an action of the details and lacks a state required by the reference, the report identifies both facts.
